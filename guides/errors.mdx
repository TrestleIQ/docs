## HTTP error codes

| Status | Name | When it occurs |
|---|---|---|
| `400` | Bad Request | Malformed request, missing required parameters, or invalid parameter values |
| `403` | Forbidden | API key missing, invalid, revoked, disabled, or not enabled for the product/version; unknown endpoint path |
| `429` | Too Many Requests | QPS rate limit or monthly quota exceeded |
| `500` | Internal Server Error | Unexpected server-side error |

## Error response format

Gateway `403` and `429` errors return a structured JSON body: a machine-readable `errorCode`, a human-readable `message`, and a `hint` suggesting how to resolve the issue. `hint` can be a single string or a list of strings — handle both.

```json
{
  "errorCode": "AUTHENTICATION_FAILED",
  "message": "The request could not be authenticated.",
  "hint": [
    "Verify that the 'x-api-key' header is present and correctly formatted, with no extra spaces.",
    "Confirm that the API key has access to the requested product and product version.",
    "Confirm that the API key is active and has not been revoked or disabled."
  ]
}
```

| errorCode | Status | When it occurs |
|---|---|---|
| `AUTHENTICATION_FAILED` | `403` | API key is missing, invalid, revoked, or disabled, or is not enabled for this product or API version |
| `QUOTA_EXCEEDED` | `429` | Billing-period quota exhausted |
| `RATE_LIMIT_EXCEEDED` | `429` | QPS rate limit exceeded |

Branch on the HTTP status first and treat `errorCode` as detail. Earlier responses used `INVALID_API_KEY`, `MISSING_API_KEY` and `FORBIDDEN` for the cases now covered by `AUTHENTICATION_FAILED`; handle any `403` the same way.

## 400 Bad Request

The server cannot process the request due to a client-side error.

**Common causes:**
- Missing a required query parameter (e.g., `phone` on phone-based APIs)
- Invalid parameter format (e.g., malformed phone number)
- Syntax error in request URL

**Fix:** Check the required parameters listed in the API reference for the endpoint you are calling.

## 403 Forbidden

The request is understood, but the server is refusing to fulfill it.

All key and access problems return `AUTHENTICATION_FAILED`. Work through the causes in order:

| Cause | Fix |
|---|---|
| `x-api-key` header missing | Add the header to your request |
| Key incorrect | Check for trailing spaces or character errors in the key |
| Key not enabled for this product or API version | Check the endpoint version against the API reference; enable the product in the portal or contact support |
| Key disabled (portal issue) | Check your wallet balance or contact Trestle support |
| Key expired (trial users) | Renew or upgrade in the portal |

A request to an endpoint path that does not exist returns `403` with only `{"message": "Forbidden"}` and no `errorCode`. Check the endpoint URL and API version against the API reference.

## 429 Too Many Requests

You have exceeded a rate or quota limit. See [Rate limits](./rate-limits) for retry guidance.

## 500 Internal Server Error

An unexpected error occurred on the server. If this persists, contact [support@trestleiq.com](mailto:support@trestleiq.com) with the request details and timestamp.

## Partial errors

Some APIs return a `200` response with an `error` or `errors` field when partial data could not be retrieved (e.g., due to an upstream timeout). Check for this field in every response:

```json
{
  "phone_number": "2069735100",
  "is_valid": true,
  "error": {
    "name": "InternalError",
    "message": "Could not retrieve entire response"
  }
}
```

When `error` is present, the response is partial. The fields that were successfully retrieved are still usable.

## Warnings

Warnings indicate non-fatal issues with the input or response. They do not prevent a response from being returned:

```json
{
  "warnings": ["Invalid Phone", "Missing Input"]
}
```

Common warning values vary by API — see the `warnings` field documentation on each API reference page.
